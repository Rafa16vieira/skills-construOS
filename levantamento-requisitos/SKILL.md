# Levantamento de Requisitos

Herda diagnóstico do master/orquestrador. Transforma conversa solta em escopo auditável.

## Quando usar

Briefing, kickoff, mudança de escopo, alinhamento cliente × obra × projeto, checklist do que falta para orçar/projetar/executar.

## Perguntas que destravam

1. Objetivo do cliente (morar, vender, operar, regularizar) e prazo desejado?
2. Orçamento-teto ou faixa? O que é inegociável?
3. Já existe programa de necessidades / planta / restrição municipal?
4. Stakeholders decisores (quem manda parar/aprovar)?
5. Saída desejada: briefing, lista de requisitos, ou RFP interno?

## Protocolo

1. Separar: obrigatório | desejável | fora de escopo.  
2. Requisitos em linguagem verificável ("3 vagas", "pé-direito ≥ 2,70 m") — não slogan.  
3. Lacunas → perguntas 3–5 ou **[PREMISSA ADOTADA]** explícita.  
4. Impacto: prazo (`planejamento-obra`), custo (`orcamento-medicao`), docs (`burocracia-documental`), disciplinas (`coordenacao-projetos`).  
5. Mudança após baseline = possível aditivo (`contratos-licitacoes`).

## Formato de saída

1–7 padrão. Incluir tabela: requisito | prioridade | origem | status (ok / a confirmar).

## Template briefing (mínimo)

- Contexto e objetivo  
- Uso, porte, local  
- Restrições (prazo, custo, norma, vizinho)  
- Requisitos funcionais e de desempenho  
- Exclusões explícitas  
- Critérios de aceite / sucesso  
- Abertos (a confirmar)
